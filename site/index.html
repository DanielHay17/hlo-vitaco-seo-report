HLTH-01The Australian sitemap lists 286 URLs, all on the NZ domainHigh›
$ curl -sL https://healtheries.com.au/sitemap.xml | grep -o '<loc>https://[^/]*' | sort | uniq -c
    286 <loc>https://healtheries.co.nz

Fix: generate one sitemap per domain. The likely cause is the generator reading the NZ site URL from shared config.

HLTH-02Pages that don't exist return HTTP 200 (soft 404)High›
$ curl -sL -o /dev/null -w '%{http_code}\n' https://healtheries.com.au/any-made-up-path
200   # page title: "Page Not Found"

Fix: return a real 404 with notFound() (App Router) or { notFound: true } (Pages Router).

HLTH-0374 of 167 product URLs return HTTP 500High›
$ curl -sL https://healtheries.co.nz/sitemap.xml | grep -o '<loc>[^<]*/product/[^<]*' \
    | sed 's/<loc>//' | xargs -P 8 -I{} curl -s -o /dev/null -w '%{http_code}\n' {} | sort | uniq -c
     93 200
     74 500

Fix: a removed product should return 404 or 301, never 500. The work order lists all 74 URLs.

HLTH-04Homepage <title> is "Home". WordPress already has the right one.High›
$ curl -sL https://healtheries.com.au/ | grep -oE '<title>[^<]*|og:title" content="[^"]*'
<title>Home
og:title" content="Home - Healtheries

Fix: build <title> from the same Yoast field the front end already uses for og:title.

HLTH-05Structured data exists in the CMS but never reaches the pageHigh›
$ curl -sL https://healtheries.com.au/ | grep -c '<script type="application/ld+json"'
0   # Yoast's schema graph is in the payload as escaped text, with URLs on api.healtheries.au.production.beingbui.lt

Fix: render the Yoast schema as a JSON-LD tag with the public host, and add Product schema. This is how AI and Google read price, ingredients and availability.

HLTH-06No canonical tags, no hreflang between AU and NZHigh›
$ curl -sL https://healtheries.com.au/ | grep -cE 'rel="canonical"|hreflang'
0

Fix: add a self-referencing canonical, plus reciprocal en-AU / en-NZ hreflang between matching pages.

NL-01Nutra-Life AU and NZ each point only to themselvesHigh›
$ curl -sL -A "Mozilla/5.0" https://nutralife.com.au/ | grep -o 'hreflang="[^"]*" href="[^"]*"'
hreflang="x-default" href="https://nutralife.com.au/"
hreflang="en" href="https://nutralife.com.au/"
hreflang="zh-Hans" href="https://nutralife.com.au/zh"

Why: they share products (Gut Relief, Magnesium Sleep, Probiotica) and compete with each other for the same searches. Fix: reciprocal en-AU ↔ en-NZ hreflang on both sites.

NL-02The NZ site declares itself AustralianMedium›
$ curl -sL https://www.nutralife.co.nz/ | grep -oE '<html[^>]*lang="[^"]*"|"inLanguage":"[^"]*"'
<html lang="en-AU"
"inLanguage":"en-AU"   # ×3

Fix: one setting. Settings → General → Site Language → English (New Zealand). It fixes all four values.
