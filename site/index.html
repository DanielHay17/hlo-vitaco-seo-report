02 · Findings with evidence

Every claim comes with a command you can run.

Each finding includes the request that proves it, why it matters and the specific change that fixes it. Output shown is from 11 October 2026.

Healtheries

Agency-owned Next.js build
HLTH-01

The Australian sitemap contains no Australian pages

High 
$ curl -sL https://healtheries.com.au/sitemap.xml | grep -o '<loc>https://[^/]*' | sort | uniq -c
    286 <loc>https://healtheries.co.nz

Why it matters

A sitemap tells Google which pages to crawl. This one sends Google to the NZ site, so the only way Google can find Australian pages is by following links.

Fix

Build the sitemap per domain. The most likely cause is the sitemap generator reading the NZ site URL from shared configuration. The agency can confirm that quickly.

HLTH-02

Pages that don't exist return HTTP 200 (soft 404s)

High 
$ curl -sL -o /dev/null -w '%{http_code}\n' https://healtheries.com.au/any-made-up-path
200
$ curl -sL https://healtheries.com.au/any-made-up-path | grep -o '<title>[^<]*'
<title>Page Not Found

Why it matters

The page says "not found" but the status code says it exists. Crawlers spend their time on junk URLs, and real broken links never show up as 404s in Search Console, so nobody gets alerted.

Fix

Return a real 404 status: notFound() in the App Router, or return { notFound: true } in the Pages Router. The not-found template can stay exactly as it is.

HLTH-03

74 of 167 product URLs return HTTP 500

High 
$ curl -sL https://healtheries.co.nz/sitemap.xml | grep -o '<loc>[^<]*/product/[^<]*' \
    | sed 's/<loc>//' | xargs -P 8 -I{} curl -s -o /dev/null -w '%{http_code}\n' {} | sort | uniq -c
     93 200
     74 500

Why it matters

When a host keeps returning 5xx errors, Google crawls the whole site more slowly and eventually drops the failing URLs. The sitemap is actively sending crawlers to these errors.

Fix

The work order lists all 74 URLs. The likely culprits are products deleted or renamed in the CMS whose routes still exist, or a data fetch that throws instead of returning 404. A gone product should return 404 or 301, never 500.

HLTH-04

The homepage title is "Home". WordPress already has the right one.

High 
$ curl -sL https://healtheries.com.au/ | grep -oE '<title>[^<]*|og:title" content="[^"]*'
<title>Home
og:title" content="Home - Healtheries

Why it matters

The <title> is the blue link in Google's results. Yoast in the WordPress backend already generates "Home - Healtheries", and the front end uses it for og:title. But it builds <title> from the raw page name.

Fix

A small front-end change: take <title> from the same Yoast field the og:title already uses. Every page then gets the titles the content team has written.

HLTH-05

Structured data exists in the CMS but never reaches the page

High 
$ curl -sL https://healtheries.com.au/ | grep -c '<script type="application/ld+json"'
0
$ curl -sL https://healtheries.com.au/ | grep -o 'yoast-schema-graph' | wc -l
1   # present, but as escaped text inside the framework's data payload

Why it matters

Product structured data drives price, availability and review details in Google's product results and merchant listings. Yoast builds the schema graph, but the front end only passes it along as escaped text and never renders a <script> tag. The URLs inside it also point at api.healtheries.au.production.beingbui.lt, not the public domain.

Fix

Render the Yoast schema graph as a JSON-LD tag, rewriting the API host to the public domain. Add Product schema on product pages, using Musashi's markup as the reference.

HLTH-06

No canonical tags, no hreflang between AU and NZ

High 
$ curl -sL https://healtheries.com.au/ | grep -cE 'rel="canonical"|hreflang'
0

Why it matters

Two domains serve near-identical product pages with nothing telling Google which version belongs to which country. Combined with HLTH-01, Google has every reason to rank the NZ pages in Australia.

Fix

Add a self-referencing canonical on every page, plus reciprocal en-AU / en-NZ hreflang between matching pages. Same pattern as NL-01 below.

Nutra-Life

Shopify (AU) + WordPress (NZ)
NL-01

Two sites, each pointing only to itself

High 
$ curl -sL -A "Mozilla/5.0" https://nutralife.com.au/ | grep -o '<link rel="alternate" hreflang[^>]*>'
<link rel="alternate" hreflang="x-default" href="https://nutralife.com.au/">
<link rel="alternate" hreflang="en" href="https://nutralife.com.au/">
<link rel="alternate" hreflang="zh-Hans" href="https://nutralife.com.au/zh">
$ curl -sL https://www.nutralife.co.nz/ | grep -o '<link rel="alternate" hreflang[^>]*>'
<link rel="alternate" hreflang="en" href="https://www.nutralife.co.nz" />
<link rel="alternate" hreflang="zh-hans" href="https://www.nutralife.co.nz/?lang=zh-hans" />

Why it matters

Both sites declare themselves as generic en. Neither mentions the other. They sell the same products (Gut Relief, Magnesium Sleep, Probiotica), so to Google they are two unrelated English sites competing for the same searches.

Fix

Add reciprocal hreflang: en-AU on .com.au, en-NZ on .co.nz, each pointing to the other's matching product, with one x-default. Hreflang only works when it is reciprocal, so both platforms need the change. The product mapping becomes a Shopify metafield.

NL-02

The NZ site tells search engines it is Australian

Medium 
$ curl -sL https://www.nutralife.co.nz/ | grep -oE '<html[^>]*lang="[^"]*"|"inLanguage":"[^"]*"'
<html lang="en-AU"
"inLanguage":"en-AU"
"inLanguage":"en-AU"
"inLanguage":"en-AU"

Why it matters

Both values come from the same source, WordPress's site language setting. Yoast uses that setting to fill in inLanguage. As a result, the NZ site reinforces the AU/NZ confusion from NL-01.

Fix

One setting: Settings → General → Site Language → English (New Zealand). This fixes the html lang and all three JSON-LD values at once. It's the smallest fix in this report.

04 · The loop

Find. Fix. Prove it moved.

An audit is a snapshot. Healtheries didn't break today and won't stay fixed by itself. The loop runs every month, so a broken site gets caught within weeks instead of years.

  1. 01

    Find

    A scheduled scan of all six sites. Plain HTTP checks (sitemaps, status codes, titles, canonicals, hreflang, rendered JSON-LD) cost nothing to run. DataForSEO adds where the brands rank, with a hard spending cap per run. Every technical finding in this report can be reproduced with it.

  2. 02

    Fix

    An agent connected through MCP to each site's builder drafts the change. A person approves it, the agent applies it, and the change is logged with before and after. When we don't have write access, the same agent writes a precise work order instead.

  3. 03

    Re-check

    The same scan runs a month later and compares results line by line: fixed, still open, newly broken. Work orders close automatically when their acceptance test passes, whoever made the fix.

Everyone sells find. Almost nobody sells fix.

Here is exactly where the loop closes by itself and where it hands off to someone else. Vitaco has three kinds of stack, so the loop closes in three different ways.

Closes automatically

Shopify

musashi.com · nutralife.com.au
  1. The agent drafts the change through the Shopify Admin API: theme files, metafields, SEO fields, redirects
  2. A person approves the diff
  3. The change is applied and logged with before/after
  4. The re-check confirms it worked
Every change can be rolled back. Nothing goes live without approval.
Closes with access

WordPress / WooCommerce

nutralife.co.nz · aussiebodies.com
  1. With a scoped application password, the agent works like it does on Shopify, through the WordPress REST API
  2. Without one, it produces a work order
  3. Settings-level fixes like NL-02 are a two-minute job for whoever holds the admin login
Your choice, site by site. Both routes are measured the same way.

05 · What I'd do first

One loop, 30 days, measured.

A small, fixed scope with numbers agreed upfront, so the result speaks for itself. If the numbers don't move, you've spent very little finding that out.

Method & sources

Technical checks

Plain HTTP requests to each live site on 11 October 2026: sitemaps, status codes, titles, canonical and hreflang tags, and rendered JSON-LD. No paid tools, nothing logged in. Sites change, so re-run the commands to see the current state.

Search data

DataForSEO Google organic results for Australia, desktop, top 10. We use a fixed endpoint and refuse search operators, because each one bills as an extra query.

What we didn't see

No Search Console, analytics or sales data. Indexation and traffic impact are estimates until Search Console is connected, and that's one of the first things the loop would add.
